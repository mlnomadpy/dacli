# frontend-quality
Honor the dashboard data contract and read-only boundary. Cover loading, empty, error, and live states. Prefer semantic HTML, keyboard access, sufficient contrast, responsive layouts, and shared component/composable patterns. Measure polling, rendering, and list growth before adding complexity. Run unit tests, type-check, lint, and production build for changed UI surfaces.
