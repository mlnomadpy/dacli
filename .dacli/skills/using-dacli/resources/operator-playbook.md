# Full dacli operator playbook

Measure the workspace first: identity/grant, project, task state, live agents,
runtime health, loop state, branch, and dirty paths. Choose direct work, one
spawn, a claimed worktree wave, supervision, or a bounded loop according to the
coordination need.

Treat exit 3 as a policy decision and follow its named remedy. Use narrow claims
and isolated worktrees for parallel writes. Detached runs require `wait`; read-
only proposals require `sync`. Run mutation evidence and repository checks,
commit through dacli, push the task branch, open a PR, wait for CI, confirm trunk
advanced, then accept and synchronize GitHub.

Projects scope scheduling and reporting; they are not storage or access-control
boundaries. Task references and the event log remain workspace-wide. Runtime
adapters are replaceable; the workspace record, not a vendor transcript, is the
provider-neutral result channel.
