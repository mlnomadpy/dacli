# using-dacli

Measure identity, project/task state, live agents, runtime health, loop state,
branch, and dirty paths before acting. Read the complete task and repository
instructions. Work only inside the truthful claim and your own worktree.

Exit 3 is a policy decision: follow its remedy and never retry unchanged.
Reproduce defects, make the regression fail under a relevant mutation, and
record commands actually run. Detached agents require `wait`; read-only
proposals require `sync`. Use `dacli commit` for attribution.

GitHub is the human collaboration surface. Check for duplicate issues, preview
broad synchronization, push the task branch, wait for every required check,
confirm trunk contains the change, then accept and close. A plan line, green
local test, or process exit is not proof of a remote mutation or landing.

Projects scope scheduling and reporting, not task visibility or security.
Runtime adapters are replaceable; the dacli event/task/run record is the
provider-neutral result channel. Record uncertainty and leave incomplete work
open rather than manufacturing a successful-looking report.
