# dacli role add (store.CreateRole) writes unconditionally to the shared main-worktree .dacli, not the calling worktree
internal/store/roles.go CreateRole takes w *workspace.Workspace and writes w.RolePath(name) directly. w comes from clikit.OpenWorkspace -> workspace.Find(ctx.Cwd), which for a LINKED git worktree redirects to the MAIN worktree's .dacli (workspace.go:80-93, by design, so all agents share one task/note/agent record). But a role file is git-tracked content, not an append-only event: running 'dacli role add estimator ...' from inside this task's isolated worktree (.dacli/worktrees/add-an-estimator-role...) wrote the new role.md into the MAIN checkout's working directory (verified: git -C <main-root> status showed '?? .dacli/roles/estimator.md' on the main checkout's own branch, 'main', while the calling worktree's local .dacli/roles/ never got the file at all). vcs.go's cmdCommit deliberately uses ctx.Cwd, not w.Root, for git add/commit (comment at vcs.go:49-53) specifically so worktree commits land on the worktree's own branch -- but that only works if the mutated file was actually written under ctx.Cwd. CreateRole (and by the same code shape CreateProject, CreateRisk, GlossaryAdd) writes under w.Root regardless, so a worktree-isolated agent's role/project/risk/glossary creation can never be committed via its own branch/PR without hand-copying the file -- it either lands as a stray uncommitted file on the main checkout's currently-checked-out branch, or is silently lost if nobody notices. This is the same class already fixed once for catalog's --out path (finding 081, decision 'catalog-out-resolves-against-ctx-cwd-caller-not-w-root') and for vcs commit's git directory -- but not yet applied to the CreateRole/CreateProject/CreateRisk/GlossaryAdd write paths themselves. Worked around for task 229 by hand-authoring the role file directly under the calling worktree's own .dacli/roles/ (matching CreateRole's exact frontmatter shape) instead of using 'dacli role add'. Not fixing in this diff -- out of scope for an estimator-role task and touches several other creation paths (project/risk/glossary) beyond roles alone.
