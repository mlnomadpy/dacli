# Reconcile reused PR bodies before land-then-accept shipping
## Context
Adopted from GitHub issue #882.

## Symptom

A land-then-accept ship transaction reused an existing open PR whose body had been generated by an older dacli version. The body still contained an auto-close keyword for the mapped issue. GitHub closed the issue immediately after the merge, before dacli completed fresh-trunk verification and local acceptance. The reused body also retained findings that the newer least-disclosure completion path intentionally does not publish.

## Evidence

On PR #881, GitHub recorded the merge at 2026-08-28T15:04:19Z and issue #841 closed at 2026-08-28T15:04:20Z. The ship transaction performed fresh-trunk verification and acceptance afterward, then found the issue already closed. No private run identifiers are reproduced here.

## Suspected cause

The PR creation path now omits auto-close keywords for nonterminal tasks, but the integration/ship reuse path trusts an already-open PR body without reconciling it to the current task lifecycle and disclosure policy before merge.

## Manual recovery

Sanitize the merged PR body, reopen the mapped issue, and close it again through the explicit closure-only projection after confirming the task is locally done and the reviewed head is on fresh trunk.

## Acceptance criteria

- A ship transaction that reuses an open PR for a nonterminal task inspects and reconciles lifecycle-sensitive closing keywords before merge.
- Reused PR bodies cannot close mapped issues until fresh-trunk verification and local acceptance succeed.
- Reconciliation removes or refuses stale disclosure-bearing sections that are outside the current publication policy, without silently deleting intentional human-authored content.
- A regression test starts with a stale existing PR body, proves the issue remains open through merge, and proves closure occurs only through the post-accept closure-only projection.
- Dry-run reports whether an existing PR body requires reconciliation, and failures leave the task and issue in an actionable nonterminal state.

## Non-goals

This does not make ordinary GitHub issue/PR publication private, and it does not broaden ship into general PR-body rewriting.
