Authority, separated

Autonomy works when every participant has one job.

dacli does not replace the orchestrator or the coding agent. It keeps their work inside a process whose claims can be checked after the model session is gone.

A

Agent judgment

The orchestrator interprets goals, decomposes work, and judges evidence. Coding agents implement, test, and review inside their assigned scope.

D

What dacli controls

Task graphs, routing, claims, worktrees, budgets, checkpoints, review identity, failure policy, and the exact GitHub landing transaction.

H

What stays human

Product direction, credentials, exceptions, emergency stop, hybrid-provider authority, and every tag or public release decision.

One governed transaction

From the next critical task to evidence on trunk.

Every transition consumes recorded state and produces the next inspectable checkpoint. A refusal is an answer; unknown external state fails closed.

  1. 01
    Plan

    Select work that moves the critical path

    Dependencies, slack, priority, capacity, and path claims determine the ready frontier.

  2. 02
    Execute

    Isolate workers before they write

    Each coding agent gets a scoped brief, bounded budget, declared harness, worktree, and non-overlapping claim.

  3. 03
    Verify

    Run the contracts that changed

    Repository-aware routing chooses structured commands and working directories for the affected paths.

  4. 04
    Review

    Exact-tree review, not a generic approval

    An independent reviewer binds its verdict to identity, branch, commit, and tree. Corrections require a fresh review.

  5. 05
    Land

    Observe GitHub before recording completion

    Checks, reviews, merge state, and fresh trunk evidence must agree before acceptance and issue closure.

Boundaries worth asking about

The safe default is explicit.

Does dacli switch coding CLIs when one fails?

No. A Codex run stays on Codex. Cross-CLI routing requires an explicit harness allowlist and `--hybrid`; installing another CLI does not authorize fallback.

Does it publish internal findings to GitHub?

Not by default. Public repositories receive the typed public-safe projection. Internal findings, decisions, and verdicts need separate repository authority and an explicit request.

Can it run forever?

Continuous operation is repeated bounded transactions with durable checkpoints—not an unbounded permission grant. Budgets, idle policy, no-progress halts, STOP, and human release authority remain active.
